# Руководство по созданию модов для визуальной новеллы «Перемены» (Changes)

Добро пожаловать в руководство по моддингу! Игра «Перемены» имеет встроенную систему модов, которая позволяет авторам добавлять свои события, диалоги, изменять переменные и создавать собственные настройки для игроков.

**Версия движка:** Ren'Py 8.5.3
**Язык программирования:** Python / Ren'Py Script

---

## 1. Структура папок мода

Все моды должны находиться в папке `game/mods/`. Каждый мод должен лежать в отдельной папке. Имя папки может быть любым, но рекомендуется использовать латиницу.

Пример правильной структуры:
```text
game/
  mods/
    my_first_mod/
      mod.rpy       <-- Главный файл вашего мода
      images/       <-- (Необязательно) Ваши картинки
      audio/        <-- (Необязательно) Ваша музыка
Каждый мод начинается с регистрации. Создайте файл mod.rpy внутри папки вашего мода и используйте следующий шаблон:
"# game/mods/my_first_mod/mod.rpy

init python:
    # 1. РЕГИСТРАЦИЯ МОДА
    # mod_id должен быть УНИКАЛЬНЫМ, только латиница и подчеркивания, без пробелов!
    register_mod(
        mod_id="my_first_mod",
        name="Мой первый мод",
        version="1.0.0",
        author="Ваше Имя",
        description="Краткое описание того, что делает этот мод."
    )
    
    # 2. ПОДПИСКА НА СОБЫТИЯ (ХУКИ)
    # Список доступных хуков смотрите в разделе 3.
    register_hook("day_start", "my_first_mod")
    register_hook("after_load", "my_first_mod")


# 3. ИНИЦИАЛИЗАЦИЯ ПЕРЕМЕННЫХ
# Используйте init 10, чтобы переменные создавались после загрузки менеджера модов
init 10 python:
    # Создаем настройку мода в persistent (сохраняется навсегда)
    if persistent.my_first_mod_extra_text is None:
        persistent.my_first_mod_extra_text = True
        
    # Создаем локальную переменную (сохраняется только в слоте сохранения игры)
    if not hasattr(store, "my_mod_counter"):
        store.my_mod_counter = 0"

Доступные события (Хуки)
Хуки — это точки в сценарии игры, куда могут «вклиниться» моды. Чтобы ваш код выполнился в нужный момент, подпишитесь на хук через register_hook и создайте специальный label.

Список доступных хуков:

"new_game" — Вызывается один раз при старте новой игры (после ввода имени).

"day_start" — Вызывается в начале каждого нового игрового дня.

"day_end" — Вызывается перед сном/переходом на следующий день.

"after_load" — Вызывается сразу после загрузки сохранения.

Как писать код для хуков?
Имя метки (label) должно быть строго по шаблону: mod_<ваш_mod_id>_<название_хука>.
Важно: В конце метки всегда должен быть return, а не jump!

"label mod_my_first_mod_day_start:
    # На всякий случай проверяем, включен ли мод
    if not mod_enabled("my_first_mod"):
        return
        
    $ store.my_mod_counter += 1
    
    # Если включена настройка мода и это 2-й день игры
    if persistent.my_first_mod_extra_text and store.my_mod_counter == 2:
        "Система" "Мод 'Мой первый мод' активен! Это второй день."
        
    return"

 Создание меню настроек мода
Игроки могут включать, выключать и сортировать моды в главном меню игры. Также они могут настраивать каждый мод отдельно!

Чтобы ваша кнопка «Настроить» появилась в меню игры:

Создайте экран с именем строго mod_settings_<ваш_mod_id>.

В меню игры он появится автоматически.
"screen mod_settings_my_first_mod():
    tag menu
    modal True
    
    # Темный фон в стиле менеджера модов
    add Solid("#1a1510E6")
    
    frame:
        xpos 0.2
        ypos 0.2
        xsize 0.6
        ysize 0.6
        background Solid("#3b3024D9")
        padding (20, 20)
        
        vbox:
            spacing 20
            text _("Настройки: Мой первый мод") size 28 color "#ffffff" bold True
            
            # ВАЖНО: Квадратные скобки в тексте нужно удваивать [[, 
            # чтобы Ren'Py не пытался найти переменную [X]
            $ btn_text = _("[[X] Включить дополнительные диалоги") if persistent.my_first_mod_extra_text else _("[[  ] Включить дополнительные диалоги")
            
            textbutton btn_text:
                action SetField(persistent, "my_first_mod_extra_text", not persistent.my_first_mod_extra_text)
                text_size 20
                text_color "#d1c1a9"
                text_hover_color "#ffffff"
                
            null height 20
            
            # Кнопка возврата в меню модов
            textbutton _("Назад"):
                action Return()
                text_size 20
                text_color "#8fbc8f"
                text_hover_color "#ffffff"
"
Сохранение данных
В модах вы можете использовать две модели хранения данных:

persistent.<имя_переменной>

Для чего: Глобальные настройки мода (вкл/выкл функции).

Особенность: Сохраняется навсегда, даже если игрок удалит все сохранения и начнет новую игру.

store.<имя_переменной>

Для чего: Сюжетные переменные, счетчики дней, отношения.

Особенность: Сохраняется только внутри конкретного сохранения игры. Если игрок загрузит другой слот, значение будет другим.

Взаимодействие с менеджером модов
В игре реализован мощный менеджер, и вам как автору нужно знать о двух вещах:

Порядок загрузки (Load Order): Игрок может менять порядок модов стрелочками. Если два мода используют один хук (например, day_start), они выполнятся в том порядке, который выбрал игрок. Это полезно, если ваши диалоги зависят от событий другого мода.

Конфликты: Если в игре включено два мода, использующих один хук, менеджер автоматически подсветит это красным. Это не ошибка, но предупреждение для игрока.

Золотые правила моддинга
Не ломайте игру: Не переопределяйте базовые функции и переменные основной игры, если это не обязательно. Старайтесь добавлять новое, а не переписывать старое.

Уникальность: Всегда используйте уникальный mod_id. Если два мода имеют одинаковый ID, второй просто не загрузится.

Экранирование скобок: Всегда пишите [[ и ]], если хотите вывести квадратные скобки в тексте (например, [[X]), иначе игра выдаст ошибку ValueError: expected expression.

return в метках: В хуках (mod_your_id_day_start) всегда используйте return. jump сломает игровой процесс, и игра вернется в главное меню.

Тестирование: Перед публикацией мода проверьте, как он работает на чистой игре и как он работает вместе с другими модами.
