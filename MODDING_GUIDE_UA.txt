
# Посібник зі створення модів для візуальної новели «Перемены» (Changes)

Ласкаво просимо до посібника з модифікації! Гра «Перемены» має вбудовану систему модів, яка дозволяє авторам додавати власні події, діалоги, змінювати змінні та створювати власні налаштування для гравців.

**Версія рушія:** Ren'Py 8.5.3
**Мова програмування:** Python / Ren'Py Script

---

## 1. Структура папок мода

Усі моди повинні знаходитися в папці `game/mods/`. Кожен мод має лежати в окремій папці. Ім'я папки може бути будь-яким, але рекомендується використовувати латиницю.

Приклад правильної структури:

game/
  mods/
    my_first_mod/
      mod.rpy       <-- Головний файл вашого моду
      images/       <-- (Необов'язково) Ваші картинки
      audio/        <-- (Необов'язково) Ваша музика
2. Базовий шаблон мода
Кожен мод починається з реєстрації. Створіть файл mod.rpy всередині папки вашого моду та використовуйте такий шаблон:

# game/mods/my_first_mod/mod.rpy

init python:
    # 1. РЕЄСТРАЦІЯ МОДА
    # mod_id має бути УНІКАЛЬНИМ, тільки латиниця та підкреслення, без пробілів!
    register_mod(
        mod_id="my_first_mod",
        name="Мій перший мод",
        version="1.0.0",
        author="Ваше Ім'я",
        description="Короткий опис того, що робить цей мод."
    )
    
    # 2. ПІДПИСКА НА ПОДІЇ (ХУКИ)
    # Список доступних хуків дивіться в розділі 3.
    register_hook("day_start", "my_first_mod")
    register_hook("after_load", "my_first_mod")


# 3. ІНІЦІАЛІЗАЦІЯ ЗМІННИХ
# Використовуйте init 10, щоб змінні створювалися після завантаження менеджера модів
init 10 python:
    # Створюємо налаштування мода в persistent (зберігається назавжди)
    if persistent.my_first_mod_extra_text is None:
        persistent.my_first_mod_extra_text = True
        
    # Створюємо локальну змінну (зберігається лише в слоті збереження гри)
    if not hasattr(store, "my_mod_counter"):
        store.my_mod_counter = 0
3. Доступні події (Хуки)
Хуки — це точки в сценарії гри, куди можуть «вклинитися» моди. Щоб ваш код виконався в потрібний момент, підпишіться на хук через register_hook і створіть спеціальний label.

Список доступних хуків:

"new_game" — Викликається один раз при старті нової гри (після введення імені).

"day_start" — Викликається на початку кожного нового ігрового дня.

"day_end" — Викликається перед сном/переходом на наступний день.

"after_load" — Викликається відразу після завантаження збереження.

Як писати код для хуків
Ім'я мітки (label) має бути строго за шаблоном: mod_<ваш_mod_id>_<назва_хука>.
Важливо: В кінці мітки завжди має бути return, а не jump!

label mod_my_first_mod_day_start:
    # Про всяк випадок перевіряємо, чи включений мод
    if not mod_enabled("my_first_mod"):
        return
        
    $ store.my_mod_counter += 1
    
    # Якщо включено налаштування мода і це 2-й день гри
    if persistent.my_first_mod_extra_text and store.my_mod_counter == 2:
        "Система" "Мод 'Мій перший мод' активний! Це другий день."
        
    return
4. Створення меню налаштувань мода
Гравці можуть вмикати, вимикати та сортувати моди в головному меню гри. Також вони можуть налаштовувати кожен мод окремо!

Щоб ваша кнопка «Налаштувати» з'явилася в меню гри:

Створіть екран з ім'ям строго mod_settings_<ваш_mod_id>.

У меню гри він з'явиться автоматично.

screen mod_settings_my_first_mod():
    tag menu
    modal True
    
    # Темний фон у стилі менеджера модів
    add Solid("#1a1510E6")
    
    frame:
        xpos 0.2
        ypos 0.2
        xsize 0.6
        ysize 0.6
        background Solid("#3b3024D9")
        padding (20, 20)
        
        vbox:
            spacing 20
            text _("Налаштування: Мій перший мод") size 28 color "#ffffff" bold True
            
            # ВАЖЛИВО: Квадратні дужки в тексті потрібно подвоювати [[, 
            # щоб Ren'Py не намагався знайти змінну [X]
            $ btn_text = _("[[X] Увімкнути додаткові діалоги") if persistent.my_first_mod_extra_text else _("[[  ] Увімкнути додаткові діалоги")
            
            textbutton btn_text:
                action SetField(persistent, "my_first_mod_extra_text", not persistent.my_first_mod_extra_text)
                text_size 20
                text_color "#d1c1a9"
                text_hover_color "#ffffff"
                
            null height 20
            
            # Кнопка повернення до меню модів
            textbutton _("Назад"):
                action Return()
                text_size 20
                text_color "#8fbc8f"
                text_hover_color "#ffffff"
5. Збереження даних
У модах ви можете використовувати дві моделі зберігання даних:

persistent.<ім'я_змінної>

Для чого: Глобальні налаштування мода (увімк/вимк функції).

Особливість: Зберігається назавжди, навіть якщо гравець видалить усі збереження і почне нову гру.

store.<ім'я_змінної>

Для чого: Сюжетні змінні, лічильники днів, стосунки.

Особливість: Зберігається лише всередині конкретного збереження гри. Якщо гравець завантажить інший слот, значення буде іншим.

6. Взаємодія з менеджером модів
У грі реалізовано потужний менеджер, і вам як автору потрібно знати про дві речі:

Порядок завантаження (Load Order): Гравець може змінювати порядок модів стрілочками. Якщо два моди використовують один хук (наприклад, day_start), вони виконаються в тому порядку, який вибрав гравець. Це корисно, якщо ваші діалоги залежать від подій іншого мода.

Конфлікти: Якщо в грі включено два моди, що використовують один хук, менеджер автоматично підсвітить це червоним. Це не помилка, а попередження для гравця.

7. Золоті правила модифікації
Не ламайте гру: Не перевизначайте базові функції та змінні основної гри, якщо це не обов'язково. Намагайтеся додавати нове, а не переписувати старе.

Унікальність: Завжди використовуйте унікальний mod_id. Якщо два моди мають однаковий ID, другий просто не завантажиться.

Екранування дужок: Завжди пишіть [[ та ]], якщо хочете вивести квадратні дужки в тексті (наприклад, [[X]), інакше гра видасть помилку ValueError: expected expression.

return у мітках: У хуках (mod_your_id_day_start) завжди використовуйте return. jump зламає ігровий процес, і гра повернеться до головного меню.

Тестування: Перед публікацією мода перевірте, як він працює на чистій грі та як він працює разом з іншими модами.
